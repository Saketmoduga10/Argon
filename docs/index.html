Argon

A multi agent orchestration framework built to survive its own crashes.

Argon plans a job as a graph of steps, runs independent steps in parallel, and writes every tool action to a durable journal before it runs. If the process dies halfway, Argon resumes from the journal, works out which actions already landed, and finishes the job without repeating side effects.

    Why the payment was not charged twice

    • Every action is journaled first. Argon records the action, and a key built from its tool and arguments, before the tool runs.
    • Uncertain is a real state. When a run dies mid action, the journal is left holding that action as started. Argon reads that as unknown, never as failed and never as done.
    • Recovery checks the evidence. On resume, Argon asks whether the side effect already landed. If it did, the action is reconciled and skipped. If it provably did not, the action runs again.
    • A verifier grades the result. Acceptance rules are checked against the actual files at the end, with evidence, before a run counts as succeeded.

    The benchmark

    One hundred tasks across five shapes of work. Argon and a sequential single agent baseline were given the same tasks, the same tools, and the same injected faults: 49 clean tasks, 28 with transient failures, 14 with uncertain outcomes, and 9 with full crashes.

    Measured with an offline stub model, so this tests the orchestration rather than the intelligence of any model. On this harness Argon is also slower per task, a median of 0.127 seconds against 0.032 for the baseline, because writing every action to a durable journal costs more than parallelism saves at this scale. The method and the raw results live in the repo, next to the code.
